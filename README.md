## Быстрый запуск

Требования: Node.js **20 или новее**, браузер, доступ на запись в папку данных. Отдельная СУБД и сборка frontend не нужны. Все команды выполняются в каталоге с `server.js` и `package.json`.

```bash
node --version
node server.js
```

Откройте **http://localhost:3000**. Остановить сервер: `Ctrl+C`.

На Windows можно запустить `START.bat`: он переходит в папку проекта, проверяет наличие Node.js, открывает браузер и запускает сервер. Если страница открылась раньше сервера, обновите её.

`dev` перезапускает сервер при изменении файлов. `npm install` для запуска не требуется: сервер использует встроенные модули Node.js. Зависимость Prettier нужна только для форматирования.

### Запуск через Docker

При установленном Docker с Compose:

```bash
docker compose up --build
```

Адрес: http://localhost:3000. Данные сохраняются в именованном томе `jana-data`. Остановка:

```bash
docker compose down
```

Compose по умолчанию включает демовход. Переменные AI берутся из окружения / `.env`. Архивная `data/db.json` не включается в образ из-за `.dockerignore`: при первом запуске создаются свежие данные. Удаление тома удалит историю демонстрации.

## Реализованные сценарии

### Заявка на отпуск → руководитель → HR → решение

1. Войти как Барсик, открыть «Заявки» и создать заявку с будущими датами и комментарием.
2. Указать период, который не пересекается с существующими ожидающими или согласованными заявками и укладывается в доступный остаток.
3. Войти как Мурзик: согласовать заявку с передачей на следующий этап либо отклонить.
4. Войти как Рыжик: согласовать переданную заявку окончательно либо отклонить.
5. Войти как Барсик и проверить итоговый статус, историю и уведомление. До решения HR заявка отображается как ожидающая HR.

Проверяются корректность дат, длительность (включая обе границы), лимит до 60 дней и остаток отпуска. Сотрудник видит свои заявки; руководитель — свои и заявки прямых подчинённых; HR — все. Самосогласование и повторное решение по закрытой заявке запрещены. При создании формируется демонстрационный документ `DOC-<id заявки>`.

### Назначение и прохождение обучения

1. Войти как руководитель или HR, выбрать сотрудника и назначить курс.
2. Руководитель может назначать курсы только прямым подчинённым; HR — любому сотруднику.
3. Сотрудник открывает назначенный курс, изучает материал и отвечает на вопрос.
4. Правильный ответ после ознакомления завершает курс: прогресс меняется с 0% на 50% и затем на 100%, появляется уведомление.

Доступны два курса: «Информационная безопасность» и «Основы кадровых заявок». В разделе «Обучение» руководитель или HR может выбрать нескольких сотрудников либо подразделение, задать необязательный срок и назначить курс. Повторное назначение требует отдельного подтверждения и сбрасывает прогресс выбранных сотрудников.

### AI Jana и база знаний

Задайте, например, «Как оформить отпуск?» или «Как назначить обучение?». Сервер отбирает доступные роли документы из `fixtures/knowledge.json`, ищет подходящие фрагменты и возвращает ответ с источником. HR-документы скрыты от остальных ролей.

Без ключа работает локальный поиск, не требующий интернета. При настроенном Groq сервер отправляет вопрос и найденные фрагменты, затем проверяет точное совпадение цитат с документами. При сетевой ошибке или непроверяемом ответе используется локальный источник. Для неизвестных или заблокированных чувствительных запросов предусмотрен отказ. Это поиск по демонстрационным документам, а не подключение к кадровой базе компании и не полноценная векторная RAG-система.

### Уведомления и кабинет

Есть личный профиль, сводка на главной странице, назначенные курсы, заявки и раздел уведомлений. Уведомления возникают при создании заявки, решении, назначении и завершении курса. Поддержаны отметка прочтения и переход к связанному разделу через кнопку-стрелку; наведение само по себе не выполняет переход. В интерфейсе используются кошачьи имена и аватары демонстрационных сотрудников.

### Демонстрация интеграций для HR

1. Войти как Рыжик и открыть интеграции.
2. Запустить синхронизацию кадров: сведения обновятся из локального `fixtures/personnel.json`.
3. Проверить журнал обмена и документы заявок.
4. Сохранить название и HTTPS-адрес будущего подключения.

## Границы MVP

- Реальные 1С:ЗУП и Documentolog ещё не подключены; сохранённый адрес не активирует обмен.
- JSON-хранилище предназначено для одного процесса и демонстрации, без транзакционной СУБД и промышленного масштабирования.
- Остаток отпуска поступает из демокадрового набора; согласование не выполняет полноценный кадровый перерасчёт баланса.
- Уведомления реализованы внутри приложения; email, SMS и внешние push-каналы не подключены.
- AI использует демонстрационную базу знаний и не подтверждает актуальность реальных корпоративных регламентов.
- Перед промышленным внедрением нужны корпоративная аутентификация, постоянное хранилище сессий, аудит, резервирование и реальная интеграционная обработка ошибок.
